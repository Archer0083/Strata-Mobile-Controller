## 1. 本版改了什么（对照上一轮反馈）

### 1.1 「导出的会话无法顺利导回」→ 已修好

**上一版的问题**：App 里其实有**两条互不兼容**的导出格式——

| 导出方式 | 文件里的顶层字段 |
|---|---|
| 导出一个会话（.json） | `conversation`（单数） |
| 导出全部会话（.json） | `conversations`（复数） |

而导入时，「会话抽屉」里的入口只认**单数**那个，「设置 → 会话数据」里的入口只认**复数**那个。所以你在「导出全部会话」得到一个文件，再从抽屉入口导回，就一定会看到：

> ❌ 文件缺少 conversation 字段，不是本 App 导出的会话

**这不是你操作错了，是 App 自己的通道没打通。**

**本版已修**：

- 导入入口现在会**自动识别**文件格式，单个会话和会话包都能导入；
- **两个入口都通吃**——不管你在哪导入，App 自己导出的文件都能认出来；
- 导入预览会显示「识别到 N 个会话 · M 条消息 · 导出时间 YYYY-MM-DD」，确认后 toast 提示「已导入 N 个会话（M 条消息）」；
- 顺带修复：导入后**置顶状态**、**被手动停止的回复**、**图片**都不再丢失。

### 1.2 「发送图片的对话再次打开就看不到图片了」→ 已修好

**上一版的问题**：图片只存在内存里，**没有存进数据库**。所以 App 一重启、或你切走再切回这个会话，图片就没了。

**本版已修**：图片现在会**保存到手机本地存储**（路径类似 `应用数据/attachments/会话ID/`），数据库只记路径，所以：

- 关掉 App 再打开，**图片还在**；
- 切走会话再切回来，**图片还在**；
- 导出的 `.json` 里**自带图片**（图片以 base64 内联），可以导到**另一台手机**上再导回去，图片同样能还原。

### 1.3 「monitor 缺 model state 的彩色图标」→ 已补齐

上一版的监控页只画了**一个灰色 `idle` 小胶囊**，没有颜色、没有状态说明。

**本版已按网页版（webUI）逐项对齐**，Model state 卡现在长这样：

```
Model state
  ● Idle    ● Reading    ● Generating    ● Queued    ● Error
  Waiting for a request
```

| 状态 | 颜色 |
|---|---|
| Idle | 灰 |
| Reading | 蓝 |
| Generating | 绿 |
| Queued | 橙 |
| Error | 红 |

- **当前状态**会高亮；**非当前状态**保持可辨识但颜色变淡（和网页版一致）；
- 卡片下方有说明文字：**还没发过请求时**显示「Waiting for a request」；**发过之后**显示上一次的结果，例如「last: 128 tokens at 42.1 tok/s」。

### 1.4 「卡片布局和折线颜色不如 webUI 好看」→ 已对齐

| 改动 | 上一版 | 本版 |
|---|---|---|
| **指标卡排布** | 手写 `Row`，实际是 1-2-2-2-1 的不规则形状 | **4 列整齐网格**（窄屏自动降 2 列），和网页版一致 |
| **卡片标题图标** | 无 | 每个指标卡有图标（仪表盘 / GPU / 层 / 温度 / 闪电 / 链路 / CPU / 磁盘） |
| **数值字号** | 偏小、发虚 | 与网页版一致的 32px 加粗 |
| **GPU 温度折线** | 绿色 | **橙色**（温度语义） |
| **PCIe / 磁盘读取折线** | 绿色 | **蓝色**（I/O 语义） |
| **Prefill 副线**（Speed 卡内） | 蓝色 | **深绿色**（主线的暗色副线） |
| **折线端点** | 方头 | 圆头圆角，和网页版一致 |
| **Context fill 卡** | 数值在环外、只有 1 条横条、**没有 GPU 温度条** | **150px 大环、数值在环心内**、**三条横条齐全**（Experts in VRAM / System RAM / GPU temperature），系统内存超 92% 会变红 |
| **Recent requests** | 一堆叠起来的卡片，没有表头 | **真表格**：9 列（Time / Status / Prompt / Reused / Output / Prefill t/s / Decode t/s / VRAM hit rate / Duration），大写表头；Status 是带**彩色圆点**的徽章 |
| **「Show all」** | 一个没有数字的复选框图标 | 带计数的按钮（如 `Show all (29)`） |

> 最后一个改动依赖主机端上报 `requests_kept` 字段；若你的主机版本较老，计数会退化为「本机已收到的条数」，属于正常现象，不影响其他内容。

### 1.5 「app 中没有配置 wireGuard 和如何使用这个 app 的说明」→ 新增「连接指南」页

**两个入口**（任选其一）：

- **设置 → 帮助 → 连接指南**；
- **连接页右上角的 `?` 按钮**。

页面内容：

| 章节 | 内容 |
|---|---|
| **第一次使用：三步连上主机** | ① 在主机上启动服务 → ② 手机与主机连上同一个 WireGuard 隧道 → ③ 在本 App 里新增连接配置（若还没有配置，页面会直接给一个「新增连接配置」按钮） |
| **WireGuard 配置详解** | 为什么需要隧道 / 手机端怎么装 / 主机端怎么配 / **连不上时依次检查**（隧道没起、地址填错、端口不对、Key 不匹配……） |
| **各页面是做什么的** | 对话 / 监控 / 控制 / 关于 / 设置，逐页一句话说明 |

> **重要说明**：本 App **不内置 VPN 客户端**。WireGuard 隧道需要你在**手机上装官方 WireGuard App** 并在**主机上装 WireGuard 并配置**——这是 WireGuard 的标准工作方式，App 只负责连接**隧道内的那个地址**（例如 `10.0.0.2`）。指南页里有完整步骤。

## 2. 请按 4 条闭环走一遍（每条都请截图）

### 闭环 A：导出的会话能导回来（**核心复测**）

1. 在对话页发几轮对话（**建议其中一轮带一张图片**）→ 记下这个会话；
2. **退出 App 整个**（从后台划掉，不是只按返回）→ 重新打开；
3. 进对话页 → 打开会话抽屉 → 点进那个会话 → **期望**：文字和**图片都还在**；
4. 进 **设置 → 数据 → 会话数据** → 点「**导出全部会话**」→ 得到一个 `.json`；
5. 用手机的文件管理器把这个 `.json` 挪个地方（或先删掉 App 数据里的会话）→ 回到 App → **点左侧抽屉底部的「导入会话（.json，自动识别单个/全部）」** → 选那个文件；
6. **期望**：弹出预览框，标题是「导入会话包」，摘要显示「识别到 N 个会话 · M 条消息 · 导出时间 …」→ 点确认 → toast 显示「已导入 N 个会话（M 条消息）」；
7. 打开刚导入的会话 → **期望**：对话内容完整，**图片也在**。

> **判定标准**：✅ 抽屉入口能导入 App 自己「导出全部会话」产出的文件（这是上一版的硬伤），且带图会话重启后不丢图 → 导入闭环**已解决**。

### 闭环 B：监控页逐项对照 webUI（**核心复测**）

请在**同一台手机**上分别打开「浏览器 → 主机地址的 `#monitor`」和「App → 监控」，对照：

1. **Model state 卡**：App 侧应有 5 个带彩色的圆点徽章（Idle 灰 / Reading 蓝 / Generating 绿 / Queued 橙 / Error 红），标题为「Model state」，下方有说明文字；
2. **指标网格**：App 侧每行应是 **4 张卡**（窄屏 2 张），Speed 卡独占整行 → 每行 4 张或 2 张，**不再有 1-2-2-2-1 的不规则排布**；
3. **卡片图标**：每张指标卡左上角应有小图标；
4. **折线颜色**：GPU 温度应为**橙色**，PCIe 与 Disk read 应为**蓝色**，其余绿色；
5. **Context fill 卡**：数值应显示在**环的正中间**，环下方有**三条横条**（Experts in VRAM / System RAM / GPU temperature）；
6. **Recent requests**：应为**带表头的表格**（表头是 TIME / STATUS / PROMPT / … 全大写），STATUS 是**带彩色圆点**的胶囊；超过 12 条时右上角出现 **「Show all (N)」** 带数字的按钮。

> **判定标准**：✅ 上述 6 项与浏览器版逐项一致 → 监控页对齐**已解决**。

### 闭环 C：连接指南可读可用

1. **设置 → 帮助 → 连接指南** → 期望看到「第一次使用：三步连上主机」「WireGuard 配置详解」「各页面是做什么的」三个章节；
2. 如果当前**没有保存过连接配置**，第一个步骤下方应有一个「**新增连接配置**」按钮 → 点它应直接跳到连接页；
3. 进 **设置 → 连接配置** → 右上角 `?` → 应同样打开这份指南。

> **判定标准**：✅ 指南页可打开、三章节齐全、无 Profile 时有引导按钮 → 说明文档**已补齐**。

### 闭环 D：措辞合规

1. 桌面图标名字 → 应为「**本地模型控制端**」；
2. 关于页底部开发者卡 → 副标题应为「**非官方第三方移动控制端 · 与上游项目无隶属或授权关系**」；
3. 导出一个 `.md` / `.html` 并打开 → 页脚应为「**由本地模型移动控制端导出 · 非官方第三方工具**」。

> **判定标准**：✅ 上述三处均无上游项目名残留 → 措辞**已合规**。

## 3. 已知非缺陷现象（不用报）

| 现象 | 说明 |
|---|---|
| 监控/关于/控制首次进入要等 1~2 秒 | 正常。`/metrics` 单次请求 + 页面可见才轮询 |
| 监控页「Show all (N)」里的 N 比浏览器里小 | 正常。主机端上报的 `requests_kept` 缺失时会退回「本机已收到的条数」 |
| 「控制」页显示「尚未建立连接」而不是崩溃 | 正常。这是 v0.0.9 修复的崩溃点。若你确实已连上主机，请到设置里**保存并激活** Profile |
| 关于页「量化档位 / Total slots / Build」等行不显示 | 正常。引擎未运行时 `/props` 返回 503，这些行自动隐藏；引擎运行后会显示 |
| 某一行显示 `–` | 正常。表示该字段主机本次没返回数据，**不会**影响其它行 |
| 导出的 `.json` 文件很大 | 正常。图片以 base64 内联（体积约为原图的 1.33 倍），这是为了让文件能独立还原图片 |
| App 首次进入很慢、包约 174MB | debug 包未做混淆与裁剪，正式版会小很多 |
| 需要看 API 请求流水 | 请用**手机浏览器**打开网页端的 `#api` 面板（App 端已移除该页面） |
