## 0. 背景与目标

v0.0.1 内测反馈两条：

1. 功能阻断级：对话看不到思维链与最终输出，最简问题只返回一个「?」（v0.0.2 已修复）
2. 体验级：**「APP 的 UI 界面不好看」** —— 朋友建议先调研 TRAE 移动端的 UI 设计逻辑与风格，再调整 UI 与功能设计

本文档即第 2 条的落地依据：把 TRAE 移动端的**设计逻辑**（不只是抄配色）拆成可执行的规范，再逐条落到 Flutter 代码。

**核心结论先行**：TRAE 移动端与本项目原 UI 的根本差异不在配色，而在**信息架构与内容分层**：

| 维度 | 原 UI（本项目 v0.0.1） | TRAE 移动端 |
|---|---|---|
| 导航结构 | 底部 4 Tab（对话/监控/控制/设置） | **无底部 Tab**，对话为主干全屏，任务中心收进抽屉 |
| AI 输出 | 灰色圆角气泡（有底色） | **扁平无气泡**，直接排在暖白底上 |
| 用户消息 | 主题主色气泡 | **灰色圆角气泡**（与 AI 相反） |
| 思考过程 | 独立带底色的 `ExpansionTile` 卡片 | **扁平文字链 + chevron**，默认折叠，无边框无底色 |
| 强调色 | teal（M3 容器色） | **单一紫色 `#502AA3`** |

「AI 扁平 / 用户有气泡」是 TRAE 与 ChatGPT 最显眼的一处反转 —— ChatGPT 是 AI 有气泡、用户扁平。TRAE 反过来做，视觉重心落在 AI 内容上，而不是落在对话的容器上。这与 Strata 的产品定位（AI 推理控制台）方向一致：**用户的话是背景，模型的输出是主体**。

## 1. 信息架构（IA）

### 1.1 结构决策

```
┌─────────────────────────────────────┐
│ ⫴  Strata · 我的主机            ⣿ ● │  ← 左：会话历史抽屉  右：功能入口 + 状态点
├─────────────────────────────────────┤
│                                     │
│         对话主干（全屏）              │  ← 唯一主干页面
│   AI 扁平输出 / 用户灰气泡            │
│                                     │
│                              ┌────┐ │
│                              │ ↓  │ │  ← "一键到底"悬浮回底按钮
│                              └────┘ │
├─────────────────────────────────────┤
│  ⊕   │  说点什么…            │ ( ↑ ) │  ← Composer 三键
└─────────────────────────────────────┘
```

**为什么砍掉底部 Tab**：

- 本项目五页里「对话」是唯一高频页，「监控/控制/关于/设置」是低频运维页
- 底部 5 Tab 会把 25% 的屏幕高度永久分配给低频功能，且对话页在手机上被压缩
- TRAE 的做法：对话全屏 → 顶栏右侧抽屉承载低频功能 → 视觉重心回到内容

**顶栏入口条（v0.0.9 重排）**——所有一级页面入口**统一在顶栏右侧**，顺序固定：

| 顺序 | 入口 | 图标 | 目标 |
|---|---|---|---|
| 1 | 监控 | `Icons.monitor_heart_outlined` | 仪表盘 |
| 2 | 控制 | `Icons.tune` | 引擎控制（加载/卸载模型） |
| 3 | 关于 | `Icons.info_outline` | Engine / Hardware / API 三卡 + 开发者信息 |
| 4 | 设置 | `Icons.settings_outlined` | 外观 / 连接配置 / 数据 |

- 每页 AppBar 的 `actions` 用 `TopNavEntries(exclude: TopNav.<本页>)`——**本页不出现在自己入口条里**
- 每个入口包 `Semantics(label:, button:, selected:)`，兼顾无障碍与 widget 测试的可定位性
- **v0.0.9 已删除** API Monitor 页（M2-4 遗留）：它依赖主机端 `svc.api_monitor`（**默认 false**），打开永远是「主机端未开启」空页；其唯一能力（请求流水）在 webUI `#api` 面板本就完整。模型加载/卸载能力未丢，归位「控制」页
- **v0.0.9 起「关于」提为一级页**（原藏在 设置 → 关于与服务 二级 ListTile）；**「会话数据」提为独立页**（原常驻设置页底部，与外观/连接平铺、且含「清空全部会话」等破坏性操作）

**双入口模型**（v0.2 修订，SPEC v0.3.5 口径）：

| 位置 | 入口 | 承载 |
|---|---|---|
| 顶栏**左侧** | 面板按钮 `⫴` | **会话历史抽屉**（朋友反馈①明确要求在左上方） |
| 顶栏**右侧** | 图标 `⣿` | 监控 / 控制 / 设置 / 任务执行 |

**关于抽屉体系的口径**（相对 v0.1 的修订）：v0.1 曾写「不引入完整抽屉体系（那是 M3 的任务中心才需要的）」。v0.3.5 起这条表述需要放宽 —— 原因是 **M1-12 会话历史必须有一个可达的入口**，不能等到 M3。因此本项目的口径调整为：

- **引入轻量抽屉**：仅承载「会话历史 + 新建会话」，实现上是一个 `Drawer` 挂 `ChatScreen`，不改动对话主干的任何布局
- **不做 M3 级别的任务中心抽屉**：任务列表、项目分组视图等仍留到 M3/M4，届时是**在现有抽屉内扩展分区**，而非重做导航
- 右侧功能入口保持不变，避免一次改动同时动左右两侧

**为什么左侧而不是右侧**：右侧已被功能入口占用，且会话历史是**对话场景下高频**的切换动作（换会话 ≈ 换上下文），放在左侧形成「左=上下文、右=运维」的稳定心智；监控/控制/设置是低频运维动作，放右侧不与高频动作抢注意力。

### 1.2 页面职责

| 页面 | 职责 | 入口 |
|---|---|---|
| 对话 | 与模型对话，看思维链与输出 | 默认页 |
| 会话历史 | 切换/管理既往会话、导出与导入 | 顶栏**左侧**面板按钮 |
| 任务执行 | 开启 MCP 工具调用、查看调用轨迹与停用 | 顶栏右侧 → 任务执行页（M2-8） |
| 监控 | 主机状态 / 模型 / 显存 / 日志 | 顶栏图标（第 1 位） |
| 控制 | 引擎启停、模型加载/卸载、上下文长度 | 顶栏图标（第 2 位） |
| 关于 | Engine / Hardware / API 三卡 + 开发者信息 | 顶栏图标（第 3 位，v0.0.9 提级） |
| 设置 | 外观 / 连接配置 / 数据（→ 会话数据独立页）/ 帮助（→ 连接指南） | 顶栏图标（第 4 位） |
| 连接指南 | 首次使用三步引导 + WireGuard 配置说明 + 各页面职责 | 设置 → 帮助 → 连接指南；连接页 AppBar `?` |

> **v0.0.9 已移除**：API Monitor 页（依赖主机端默认关闭的 `svc.api_monitor`，恒为空页）。
>
> **v0.0.10 新增**：连接指南页（纯说明 + 深链引导，**不内嵌 WireGuard 协议栈** —— 隧道由手机侧官方 WireGuard App 负责，本 App 只连隧道内的地址）。

## 2. 视觉语言（设计 token）

### 2.1 色彩

以 TRAE 移动端为基准，全部为**暖中性灰**而非纯灰 —— 纯灰在手机上显冷硬，暖灰更接近纸感。

| Token | Hex | 用途 |
|---|---|---|
| `bg` | `#F7F6F4` | 页面底色（暖白） |
| `surface` | `#FFFFFF` | 卡片 / 浮层 |
| `inputBg` | `#F0F0F0` | 输入框底色 |
| `textPrimary` | `#0F0F0D` | 主文字 |
| `textSecondary` | `#1B1B19` | 次级标题（AI 标题、消息正文） |
| `textTertiary` | `#949492` | 三级文字（元信息、占位符） |
| `hairline` | `#E3E2E0` | 1px 分隔线 |
| `hairlineSoft` | `#EAE9E7` | 更弱的分隔线 / 边框 |
| `accent` | `#502AA3` | **唯一交互强调色**：发送键、AI 头像、选中态、链接 |
| `accentSoft` | `#EDE6F7` | 强调色的极浅底（选中标签底） |
| `success` | `#006142` | 连接成功 / 已就绪 |
| `warning` | `#FEDCC0` | 提醒条底色 |
| `warningText` | `#7A4A12` | 提醒条文字 |
| `userBubble` | `#EBEBEB` | 用户消息气泡底 |

**强调色纪律**：`accent` 是**唯一**的紫色，只用于「可交互 / 当前选中 / 本产品标识」三处。状态色（success/warning）各自独立，不与 accent 混用。危险操作仍走 Material `error`（暖红），不引入第二套红。

> 关键取舍：TRAE 用紫色而不是蓝色/青色做强调色，是为了和「模型 / AI 身份」绑定 —— 紫色也用作 AI 头像底色，形成同一套身份语言。本项目同理：AI 头像 = 紫色圆牌。

### 2.2 圆角

| Token | 值 | 用途 |
|---|---|---|
| `radiusSm` | 10 | 小标签、内联块 |
| `radiusMd` | 12 | 输入框、按钮、卡片 |
| `radiusLg` | 14 | 消息气泡 |
| `radiusXl` | 16 | 大卡片 / Sheet |
| `radiusPill` | 999 | 胶囊标签、圆形按钮 |

### 2.3 字号与行高

| 角色 | size | weight | 备注 |
|---|---|---|---|
| 页面标题 | 17 | w600 | |
| 区块标题 | 15 | w600 | |
| 正文 / 消息 | 15 | w400 | `height 1.5` |
| 思考链文字 | 13 | w500 | accent 色 |
| 元信息 | 12 | w400 | `textTertiary` |
| 占位符 | 13 | w400 | `textTertiary` |

### 2.4 阴影

TRAE 移动端几乎不用投影，靠**底色差 + hairline** 分层。仅浮层（Sheet / 回底按钮 / 抽屉）使用极轻阴影：

```
elevation 2 → shadow: 0 2px 12px rgba(15,15,13,0.08)
```

## 3. 核心组件规范

### 3.1 消息气泡（关键反转）

```
用户消息                              AI 消息
┌──────────────────────┐              思考过程 ›
│ 灰底 #EBEBEB          │              ┌──────────────────────────┐
│ 圆角 14               │              │ 正文（无底色、无边框）      │
│ 右对齐                │              │ 直接落在页面底色 #F7F6F4   │
└──────────────────────┘              └──────────────────────────┘
```

- 用户气泡：`maxWidth` ≈ 屏宽 78%，右对齐，底 `#EBEBEB`，圆角 14，padding `h14/v10`
- AI 消息：**无任何容器**，左对齐占满可用宽度，仅靠段间距（16px）与用户消息区分
- AI 消息**不加头像行**（TRAE 移动端没有每条 AI 消息的头像，紫色只用于 Composer 侧的 AI 标识）—— 头像行会打断长文本阅读节奏

### 3.2 思考过程（Thinking）

TRAE 形态：**扁平文字链 + chevron**，默认折叠，**无边框、无底色**。

```
▸ 思考过程                    ← 13px, w500, accent 色, 右侧 chevron
                              ← 展开后：13px 次级色正文，缩进对齐左侧
```

- 与「任务耗时」**共用一条元信息带**（见 3.3），二者视觉权重一致
- 流式进行中且尚无正文时，文字链显示为「思考中…」并**自动展开**；正文一旦开始流出即折叠
- 展开态用 `AnimatedSize` 做高度过渡，避免突兀跳变

### 3.3 元信息带（Meta Strip）

AI 消息底部一条极简横带，把「思考 / 耗时 / token / 复制 / 停止」统一收纳：

```
思考过程 ›    ·    2.4s    ·    1,024 tokens    ⧉复制
```

- 12px `textTertiary`，分隔符用 `·`
- 放在 AI 正文下方，右对齐或左对齐均可（TRAE 为左对齐起排）
- 复制 / 停止按钮用 12px 图标按钮，不带边框
- **不使用胶囊标签堆叠**（旧版 usage 是独立一行 `tokens：xxx` 文本）→ 改为元信息带的一员

### 3.4 Composer（输入区）

TRAE 形态：**v0.0.9 起全盘对齐 webUI 的 Composer**（底栏四图标 + spacer + 提示 + 发送）

```
┌───────────────────────────────────────────────┐
│ 思考 中                                        │
│ ┌────┐                              ┌───────┐ │
│ │ ⊕  │  说点什么…                    │  ↑    │ │
│ │ +  │                              │ 发送  │ │
│ │ 💬 │                              └───────┘ │
│ │ ⭳ │                                          │
│ │ ⚙ │                                          │
│ └────┘                                          │
└───────────────────────────────────────────────┘
```

- 底色 `#F0F0F0`，圆角 12（多行输入时上方圆角 12、下方 16，形成"卡片贴底"观感）
- **底栏四个圆形图标键**（自左向右），与 webUI 的 `attach-btn` / `new-btn` / `export-btn` / `sampling-btn` 一一对应：
  - `⊕` **添加附件**（`Icons.add`）
  - `💬` **新会话**（`Icons.chat_bubble_outline`）
  - `⭳` **导出当前会话（Markdown）**（`Icons.download_outlined`）
  - `⚙` **采样与思考**（`Icons.tune`）→ 打开「采样与思考」抽屉
- **不再有麦克风按钮**：v0.0.9 起删除（原为 `onTap: () {}` 的占位死键；webUI 本身也没有麦克风按钮）
- 发送键：**圆形（`radiusPill`）紫色实心按钮**，内含向上箭头（非纸飞机）→ 视觉上更接近"提交"而非"发送消息"
- 忙碌时发送键变为**停止键**（方形图标，同位置同尺寸，颜色降为 `textTertiary`）
- **思考强度档位**：v0.0.9 起**不在输入框上方平铺成胶囊**（旧版的「思考 / 关闭 / 低 / 中 / 高 / 采样」六枚胶囊在窄屏必然溢出）。
  - 输入框上方只保留**一行灰色状态文字**（如 `思考 中` / `思考 关闭`），`textTertiary` 12px
  - 思考四档（关闭 / 低 / 中 / 高）**与采样参数合并进「采样与思考」抽屉**：思考档位**点击即生效**，temperature / top_p / top_k / max tokens / seed 为草稿，点「应用」才生效，抽屉底部有「重置 / 应用」
- **附件与图片的持久化契约（v0.0.10）**：
  - 图片**不存进 SQLite**：单张 dataURL 可达数 MB，入库会撑爆 DB
  - 发送时图片**落盘**到 `<app documents>/attachments/<conversationId>/m<seq>-<micros>.<ext>`，DB `messages.images_json` 只存**路径数组**
  - 内存态 `UiChatMessage.imageUrls` 暂存 **dataURL**，保证发送后立刻可渲染；重开会话时按路径读回 dataURL
  - 导出 `.json` 时用 `imageResolver` 把路径内联回 dataURL → **导出的文件自带图片，可跨机导入**


### 3.5 顶栏

```
⫴  Strata · 我的主机              ⣿  ●
```

- **左**：面板按钮 `⫴`（`Icons.menu_open` / `segmented icon` 风格，非汉堡 `≡` 也非返回箭头）→ 唤起 `ConversationDrawer`
  - 位置在**标题左侧**，与 TRAE 移动端一致（反馈①明确要求在左上方）
  - 尺寸 ≥ 44×44 点击区，图标 20–22px，`textSecondary` 着色
  - 语义上是「打开面板」而非「返回」，因此不能复用 `AppBar` 的自动返回箭头（会有歧义）
- 中：服务器名（15px w600）+ 副标题为连接状态点 + 状态文案（12px）
- 右：功能入口图标（监控/控制/设置/任务执行）+ 状态指示
- 状态点：绿 `#006142`（已连接）/ 灰（未连接）/ 红（错误）

### 3.9 任务态（MCP 工具调用）视觉

对应 SPEC v0.3.5 §8.1「MCP 工具调用」与 §11.3「MCP 工具调用的安全边界」，M2-8 落地。

由于 MCP 工具调用意味着**远程触发主机侧行为**，视觉上必须做到「全程可见、可随时叫停」，不能像普通流式输出一样默默滚过去。

**三段式呈现**（挂在该条 AI 消息下方，取代普通元信息带的位置）：

```
┌────────────────────────────────┐
│ ⚙ 调用主机工具                  │  ← 工具调用标题行（accent 图标）
│ ▸ read_file  /home/user/a.py   │  ← 可折叠的调用明细（默认折叠）
│   ✓ 已完成 · 0.8s              │
└────────────────────────────────┘
```

- **标题行**：`⚙ 调用主机工具` 14px w500 + 右侧状态徽标
  - 状态徽标三态：`执行中`（`accentSoft` 底 + `accent` 字 + 旋转指示）/ `已完成`（`success`）/ `失败`（`warningText`）
- **调用明细**：默认**折叠**，展开后每条调用一行 `工具名 + 关键参数`（参数截断至 40 字符），下挂状态与耗时
  - 折叠态在标题行后跟一个 `chevron`，与「思考过程」的展开形态**保持一致**（同一套折叠交互）
  - 折叠态摘要行显示：`调用 3 个工具 · 2.4s`，让用户不展开也能知道「有没有动我的东西」
- **调用中强制展开**：第一次工具调用发生时明细**自动展开**，直到本轮工具调用全部结束才允许手动折叠 —— 不允许「在动主机但界面看不到」
- **「停止」入口常驻**：Composer 的发送键在 MCP 轮次进行中变为停止键，点击立即中断本轮；MCP 授权面板上另有一个独立的「停用 MCP」开关（一键永久关闭，无需重进 App）
- **失败呈现**：工具报错不静默吞掉，行内红色 `warningText` 显示错误摘要 + 「查看详情」

**授权面板**（首次开启 MCP 时弹出，一次性说明 + 风险提示）：
- 标题「允许本 App 调用主机工具？」
- 三条要点：① 工具在**主机用户权限**下运行 ② 可读写主机文件 ③ **随时可在设置中关闭**
- 按钮：「同意」`accent` 实心 / 「暂不」`textSecondary` 文字
- 开关默认**关闭**（SPEC §16.4 DoD 要求「MCP 开关默认关闭」）

### 3.10 Monitor 仪表盘规范（webUI 对齐基准）

第十一轮真机反馈：「monitor 仪表盘和 webUI 还是不一样，缺少 model state 的彩色图标，而且卡片布局和折线颜色也不如 webUI 好看」。

**定位**：Monitor 页是**运维读数页**，不是聊天页 —— 它的视觉基准是 webUI 的 `metrics` 面板，两者必须**同构**（同样的信息、同样的配色、同样的层级），否则测试者无法横向对照。

**3.10.1 Model state 卡（五态彩色圆点徽章）**

```
┌─ Model state ─────────────────────────────┐
│  ● Idle    ● Reading   ● Generating        │
│  ● Queued  ● Error                         │
│  Waiting for a request                     │
└────────────────────────────────────────────┘
```

- 五枚徽章**恒定全部渲染**，不做互斥单选；每枚 = 彩色圆点 + 状态名
- 徽章色（对齐 webUI `components.css` 的 `.st-badge`）：

| 状态 | 前景（圆点/文字） | 底色 |
|---|---|---|
| Idle | `#6F6F6F` | `#F7F7F7` |
| Reading | `#0668C2` | `#E8F4FF` |
| Generating | `#0C8A60` | `#ECFDF5` |
| Queued | `#8A5A00` | `#FFF6E0` |
| Error | `#B01A2E` | `#FDECEE` |

- **双高亮规则**：当前状态 + 原状态同时高亮（原状态用描边区分），其余状态 `opacity ≈ 0.38`
- 圆点实现：**`TraeWidgets.statusDot(color, size: 6)`**（等价 webUI `.st-badge::before` 的 6px `currentColor` 圆点）
- 卡内副文案：空闲时 `Waiting for a request`；有请求时 `last: N tokens at M tok/s`

**3.10.2 指标网格（4 列）**

- 容器宽度 > 560dp → **4 列**；≤ 560dp → **2 列**（webUI CSS Grid `repeat(4, minmax(0,1fr))`，≤1000px 降 2 列）
- 8 个指标卡顺序固定：Speed / GPU load / VRAM / GPU temp / Power / PCIe / CPU / Disk read
- 每卡：**16px 标题图标 + 标题 + 大号数值 + 迷你折线**
  - 图标（对齐 webUI sprite）：Speed `i-gauge`、GPU load `i-gpu`、VRAM `i-layers`、GPU temp `i-thermometer`、Power `i-bolt`、PCIe `i-link`、CPU `i-cpu`、Disk read `i-disk`
- 数值字号 **32px / w900**（`TraeTokens.fontStat`），不要小于 20px —— webUI 的读数感来自这个对比度

**3.10.3 折线 tone 配色（不再全绿）**

| 指标 | tone | 色值 |
|---|---|---|
| Speed（主线） | accent | `#10B981` |
| Speed（prefill 副线） | accent 压深 | ≈ `#0A744D`（`Color.lerp(accent, black, 0.35)`） |
| GPU load / VRAM / Power / CPU | accent | `#10B981` |
| **GPU temp** | **warn** | **`#E39B0B`** |
| **PCIe / Disk read** | **info** | **`#0F97FF`** |

- `SparklinePainter` 必须设置 `strokeCap/strokeJoin = round`
- 线宽做**非等比缩放补偿**（等价 webUI `vector-effect="non-scaling-stroke"`）：线宽 = `1.6 / sx`，避免非正方形画布上线宽忽粗忽细

**3.10.4 Context 卡（上下布局 + 环 + 三横条）**

```
┌─ Context ─────────────────┐
│        ╭─────╮            │
│        │ 42% │            │  ← 数值在环**圆心内**
│        ╰─────╯            │
│  Experts in VRAM  ▓▓▓░░░  │
│  System RAM       ▓▓░░░░  │
│  GPU temperature  ▓▓▓▓░░  │
└───────────────────────────┘
```

- 布局：**上下居中**（不是左右），环 **150×150**
- 环轨道是 **270° 弧**（不是整圆）；**近零弧隐藏**（`sweep * 0.75 * 2π ≥ 3px` 才画）—— 避免 0% 时画出一个假点
- 三条横条**必须齐全**：Experts in VRAM / System RAM / GPU temperature（v0.0.9 漏掉了温度条）
- RAM 占用 > 92% → 横条转 `danger` 色

**3.10.5 Recent requests（9 列表格）**

- webUI 是**真 `<table>`**，App 用**大写表头 + 横向滚动**的等价物（不是堆叠卡片）
- 9 列：`TIME / STATUS / PROMPT / REUSED / OUTPUT / PREFILL T/S / DECODE T/S / VRAM HIT RATE / DURATION`
- STATUS 列是**带圆点的胶囊**：Done=accent、Max tokens=info、Canceled/Disconnect=warn、Error=danger
- VRAM hit rate 列格式：`85.3% +62% PCIe`
- 默认只显示 **12 条**；服务器上报 `requests_kept` 且 > 12 时显示右上角 `Show all (N)` 计数按钮（N 取 `requests_kept`，缺失时退回已收条数）
- 表格下方保留总计摘要行：`N requests · N prompt tokens · N reused · N output tokens`

## 4. 交互逻辑

### 4.1 流式渲染

- 正文逐块追加，无打字机动画（保持与后端节拍一致，避免"假卡顿"错觉）
- 思考链同样逐块追加，流式中自动展开
- 流结束且正文为空 → 显示「未收到回复」而非永久转圈（**v0.0.1 的次生 bug，本次一并修**）

### 4.2 状态与反馈

| 状态 | 反馈 |
|---|---|
| 未连接 | Composer 禁用 + 顶部 warning 条（`#FEDCC0` 底 + 深棕字） |
| 发送中 | 发送键变停止键；输入框仍可编辑但不发送 |
| 成功 | 消息下方元信息带显示耗时 + token |
| 失败 | 消息下方 error 行 + 「重试」文字按钮 |

### 4.3 空态

对话为空时不是一行灰字，而是**居中引导块**：标题「开始与本地模型对话」+ 副文案 + 2~3 个可点击的示例问题胶囊。
